# Проверка версии

Дата: 6 сентября 2026. Проверено локально в Windows с Docker Desktop / Linux containers.

## Выполнено

- `dotnet restore` — успешно, проверка NuGet audit включена.
- `dotnet build -c Release` — без ошибок и предупреждений.
- `dotnet test -c Release` — 22 теста: 9 unit и 13 integration, без пропусков.
- PostgreSQL интеграционные тесты используют изолированный Testcontainers-контейнер и миграции.
- Проверены повторные и параллельные события, ограничение cashback, отдельные категории и месяцы UTC.
- Проверен rollback покупки и Outbox при сбое до commit.
- Проверены API, настоящая история наград и неверные входные данные.
- RabbitMQ: публикация с подтверждением и чтение persistent сообщения.
- Redis: запись, чтение, инвалидация и fallback после остановки контейнера.
- `dotnet ef migrations has-pending-model-changes` — изменений модели вне миграций нет.
- Docker Compose: API, Worker, PostgreSQL, RabbitMQ и Redis запускаются.
- Swagger возвращает HTTP 200.
- Сквозная проверка с остановкой RabbitMQ: покупка принимается, награда ждёт, после восстановления начисляется 250 рублей.
- Повторная публикация события той же покупки не создаёт вторую награду; Consumer пишет duplicate event в лог.

## Как повторить

```bash
dotnet restore
dotnet build -c Release
dotnet test -c Release
docker compose up --build -d
```

В PowerShell, из корня проекта:

```powershell
./scripts/Smoke-Test.ps1
# Дополнительно временно остановить брокер и проверить восстановление:
./scripts/Smoke-Test.ps1 -ExerciseOutage
```

Скрипт создаёт отдельного тестового пользователя и покупки, которые остаются в demo-БД. Он ожидает исходное правило Restaurants: 5%, активное, лимит не меньше 250. При изменённых вручную правилах он сообщает об этом, не перезаписывая их.

GitHub Actions workflow добавлен, но его облачный запуск возможен только после публикации репозитория. Нагрузочные испытания, аудит безопасности и эксплуатация на реальном банковском трафике не проводились. Ограничения описаны в README.
